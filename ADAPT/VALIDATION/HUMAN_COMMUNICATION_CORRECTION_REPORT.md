## Decisions, continuation and capacity

APPROVE, REJECT and SHOW DETAILS are recognized directly. Clear equivalents include "yes, approve this action", "do not proceed" and "please show the details". Other language uses the existing model-assisted workflow and a constrained interpreted_decision. Conditional, hypothetical, quoted, conflicting or uncertain text requires clarification. Classification cannot establish identity or grant scope. Actual response text and original source reference are retained; no authentication or consent is invented.

The persisted exact plan is decision context, never a saved approval token. Details leave it unchanged. Rejection consumes only that review with no protected mutation. Multiple pending actions require selection by task name; selection must resolve exactly one, never the latest by assumption. Changed scope/source/plan requires fresh review and a fresh internally prepared operation reference. Approval is marked consumed before entering the writer; any interruption requires evidence inspection and separately authorized future action, never replay. Saved plans cannot authorize another action.

Installation scope supplies applicable identities and role evidence. One legitimate dual-capacity human can make one response; authorize emits separate Director and Maintainer capacity records with the same original reference. Missing capacity fails closed. Distinct-human organizations continue to use the existing adapter's separate approval-evidence collection; a lone response in interact cannot stand in for another human's approval. Current withdrawal is rechecked by the existing writer before mutation. The default review explicitly explains dual-capacity approval; missing capacity is named in the refusal. No recovery approval grants blocker closure, context activation, handback or another action.
